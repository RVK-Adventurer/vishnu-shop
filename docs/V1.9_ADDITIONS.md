# v1.9 additions (owner-controlled look, languages, counts, popups, branding, products, footer)

Additions to Master Build Prompt v1.8, requested by the seller on 2 October 2026. They are part of the core (every client shop gets them) and every one can be switched or changed by the owner.

**Where they are controlled:**
- **Now (before the admin website exists):** the `display` section of `client/store.config.json`, edited on GitHub. Cloudflare rebuilds the shop 1–2 minutes after you click **Commit changes**.
- **From Phase 2:** switches and choices in the admin (Settings → Branding → *Look and feel*, *Shop wording*, *Languages*; *Offers & popups*). Once the admin publishes its settings, those win over the `display` section.

**Safe, secure and free:** everything runs in the visitor's browser or at build time. No new accounts, services or costs. Owner-typed text is always shown as plain text, so nothing harmful can be typed in. Fonts are stored in the shop itself (no Google), and are downloaded only when chosen.

## 1. Page width — `page_width`

| Value | What it does |
|---|---|
| `STANDARD` | The page stops at 1280 px and centres itself |
| `WIDE` | The page stops at 1600 px |
| `FULL` (default) | Fills any screen. Zooming out or using a big monitor adds more product columns instead of leaving empty sides |

Reading text (descriptions, policy pages) keeps a comfortable line length on purpose. Product photos never grow taller than the screen. Tested at 320 px to 3840 px wide with no sideways scrolling.

## 2. Look and feel — `ui_corners`, `ui_shadows`, `ui_spacing`, `ui_text_size`, `font_body`, `font_heading`

| Setting | Choices |
|---|---|
| `ui_corners` | `SHARP` · `STANDARD` · `ROUND` |
| `ui_shadows` | `NONE` · `SOFT` · `STRONG` |
| `ui_spacing` | `COMPACT` · `COMFORTABLE` · `AIRY` |
| `ui_text_size` | `NORMAL` · `LARGE` (112.5%) · `XLARGE` (125%) |
| `font_body`, `font_heading` | `system` (phone's own font, fastest) · `poppins` · `lora` (serif) · `mukta` (good for Hindi) · `hind-madurai` (Tamil + English) · `noto-sans-tamil` · `baloo-2` (playful) |

These are fixed choices, not free sliders, so the shop can't be made unreadable. The most extreme combinations were tested on a 320 px phone in English and Tamil with no layout breaks. Colours are unchanged: theme presets or any colour, with the readability check. Preview everything at `/styleguide.html` using the pickers at the top.

Fonts: six free fonts under the SIL Open Font License 1.1 (licence file in each `public/assets/fonts/<font>/` folder). Only the chosen font is downloaded.

## 3. Ratings — `reviews_enabled`

Stars and counts come only from real buyers' reviews that the owner approved. `false` hides stars, counts and the rating filter everywhere. Owners can never type a rating by hand — see "Legal note" below.

## 4. "Bought" counts — `sold_counts_mode`, `sold_counts_min`

| `sold_counts_mode` | Shows |
|---|---|
| `OFF` | Nothing |
| `MONTH` (default) | "100+ bought in past month" |
| `TOTAL` | "1K+ bought so far" |
| `BOTH` | Product cards show the month line; product pages show both |

- `sold_counts_min` (default 10): below this, nothing is shown, so a new product never says "1 bought".
- Counted from real orders only. Cancelled, expired, refunded and returned orders don't count.
- Rounded down to 10+, 20+, 50+, 100+, 200+, 500+, 1K+, 2K+, 5K+, 10K+, 20K+, 50K+, 1L+. The exact sales of a shop are never made public.
- Phase 2/3 (Publish) writes `sold_30d` / `sold_total` for each product. They are refreshed once a day by one website refresh, well within the 12/day limit. Until real orders exist, the sample products show sample numbers.

## 5. Change any sentence — `text_overrides_json`

Every sentence the shop shows (about 320 of them) can be replaced, per language:

```json
"text_overrides_json": {
  "en": { "cart.add": "Add to bag", "home.bestsellers": "Customer favourites" },
  "ta": { "cart.add": "பையில் சேர்" }
}
```

- The sentence names (like `cart.add`) are listed in `public/strings/en.json`.
- **Rules (checked automatically):**
  - Plain text only
  - 300 characters at most
  - Words in curly brackets, like `{n}` or `{amount}`, must be kept exactly. They are filled in automatically.
- A change that breaks a rule is skipped, and the build log says why.
- The Phase 2 admin gets a "Shop wording" screen with search and the same checks.

Shop name, tagline, banners, announcement, trust strip, policy pages, footer text and product details are edited in their own settings as before.

## 6. Second language — `languages_json`, `default_language`

- `["en"]` = English only. `["en", "ta"]` = English and Tamil, with a language picker in the header (globe icon), and in the menu on phones.
- The main language lives at the normal addresses. The other one gets its own copy of every page under `/ta/` (for example `/ta/p/kaju-katli/`), so Google can list both and WhatsApp previews work in both.
- `"default_language": "ta"` makes Tamil the main language and moves English to `/en/`.
- **The Tamil text in `public/strings/ta.json` is a careful draft. Have a native Tamil speaker check it before going live.** Any sentence missing there is shown in English automatically.
- Product names and descriptions stay in the language the owner types them in. Two-language product details is a separate, bigger feature for later.
- Hindi: the switcher already supports `hi`. Adding `public/strings/hi.json` (a translation of `en.json`) turns it on.
- Each extra language doubles the number of pages. That's fine up to about 9,000 products (Cloudflare's limit is 20,000 files).

## 7. Timed announcement — `announcement_text`, `announcement_starts_at`, `announcement_ends_at`

The owner's own top-bar message can have a start and end. It appears and disappears by itself, re-checked in the visitor's browser every minute. Dates are India time, for example `2026-10-20T09:00:00+05:30`. Banners (`hero_banners_json`) accept the same `starts_at` / `ends_at`. When no banner is running, the branded welcome banner shows instead.

## 8. Offer popups — `popups_json`

```json
"popups_json": [{
  "id": "diwali26",
  "active": true,
  "title": "Diwali Sale — 20% off",
  "text": "On all sweets and gift boxes.",
  "image": "",
  "image_alt": "",
  "code": "DIWALI20",
  "cta_text": "Shop sweets",
  "cta_link": "/c/sweets-snacks/",
  "starts_at": "2026-10-20T00:00:00+05:30",
  "ends_at": "2026-11-02T23:59:00+05:30",
  "frequency": "DAY",
  "pages": "ALL",
  "delay_seconds": 2
}]
```

| Field | Meaning |
|---|---|
| `id` | Any short unique name. Change it to show a new offer to people who closed the old one. |
| `active` | `false` switches it off without deleting it |
| `image` | Optional poster picture stored in the shop, for example `client/assets/poster-diwali.jpg` (JPG, PNG or WebP, under 500 KB, best 1080 × 1350). Pictures from other websites are blocked for safety. |
| `image_alt` | Short description of the poster for blind customers (needed for poster-only popups) |
| `code` | Optional coupon code, shown with a **Copy code** button |
| `cta_text` / `cta_link` | Optional button; a link inside the shop (starting with `/`) or a full `https://` address |
| `starts_at` / `ends_at` | When it runs (India time) |
| `frequency` | `DAY` = once per visitor per day · `SESSION` = once per visit · `ONCE` = only ever once |
| `pages` | `ALL` or `HOME` (home page only) |
| `delay_seconds` | Wait before showing, 0–30 (default 2) |

**Poster popups:** give an `image` and leave out `title` and `text`. The whole poster is shown, never cropped, sized to fit the screen, and tapping it opens `cta_link`. The coupon box and an optional button (`cta_text`) sit underneath. With a title as well, the picture sits above the words. The poster is loaded before the popup opens, so customers never see an empty box. If the picture is missing, a poster-only popup is quietly skipped, and the build log says why. Setup Guide step 8c has the click-by-click steps. From Phase 2, the admin's *Offers & popups* screen gets an **Upload poster** button that shrinks big pictures automatically.

**Kind by design:**
- Only one popup at a time.
- Never on cart, checkout, payment or order pages.
- Always closable with the ✕, Esc, a tap outside, or a swipe down on phones.
- On phones it slides up as a card instead of covering the page.

The coupon code itself must also exist in Coupons (Phase 3) to actually give the discount.

## 9. Home page sections and menus — `home_layout`, `home_sections_json`, `show_category_menu`, `show_all_products_link`

**Home page style — `home_layout`**

| Value | What the home page shows |
|---|---|
| `A` (default) | The sections listed in `home_sections_json`, in that order |
| `B` | Every product on one page, with filters, sort and "Load more" (plus the trust strip if `trust` is listed) |

**Sections — `home_sections_json`** (used with `A`). List the sections you want, in the order you want them. Leave a name out to hide it.

| Name | Section |
|---|---|
| `banner` | The big banner at the top |
| `trust` | Trust strip (secure payments, COD, returns, delivery) |
| `categories` | "Shop by category" picture tiles |
| `pinned` | Your own hand-picked rows (from Phase 2) |
| `bestsellers` | Bestsellers |
| `new_arrivals` | New arrivals |
| `deals` | Deals (products with a discount) |
| `recently_viewed` | The customer's recently viewed products |
| `all_products` | Every product, with filters and sort. Best placed last |

Default: `["banner", "trust", "categories", "pinned", "bestsellers", "new_arrivals", "deals", "recently_viewed"]`

Example (banner, then bestsellers, then all products): `"home_sections_json": ["banner", "bestsellers", "all_products"]`

- Product rows appear only when at least 4 products fit them (for example, Deals needs 4 discounted products in stock). This is so a row never looks empty.
- If nothing would show, the first 12 products appear, so the home page is never blank.
- A misspelt name is skipped, and the build log says so.

**Menus**

| Setting | Meaning |
|---|---|
| `show_category_menu` | `true` (default) shows categories in the header bar, phone menu and home tiles. `false` hides them everywhere; category pages still work, and customers browse via search and "All products". |
| `show_all_products_link` | `true` (default) puts an **All products** link first in the header bar. It opens one page with every product, filters and sort. |
| Per category: `show_in_menu` | From Phase 2, each category gets a "Show in menu" switch, to hide one category from menus and tiles while its page and products stay. "Active" off hides the category completely. |

From Phase 2, these are switches and an up/down list in Admin → Settings → Layout.

## 10. Logo, favicon and tab names — `logo_path`, `logo_mode`, `logo_height_px`, `favicon_path`, `tab_title_format`, `tab_title_home`

| Setting | Meaning | Limit |
|---|---|---|
| `logo_path` | Your logo file, e.g. `client/assets/logo.png` (SVG, PNG, WebP or JPG) | under 300 KB |
| `logo_mode` | `LOGO_AND_NAME` (default) · `LOGO_ONLY` · `NAME_ONLY` | — |
| `logo_height_px` | Logo height on computers | **24 to 72 pixels** (default 40). Phones always use at most **44**. A value outside the limits is changed to the nearest limit, and the build log says so |
| `favicon_path` | The small icon in the browser tab, e.g. `client/assets/favicon.png` | Square PNG or SVG, best 512 × 512, under 200 KB |
| `tab_title_format` | Name shown on every page's browser tab. `{page}` = the page, `{shop}` = shop name. Default `{page} — {shop}`; example `{page} \| {shop} Online` | must contain `{page}`; Google shows about 60 characters |
| `tab_title_home` | The home page's tab name (empty = the SEO title from setup) | about 60 characters |

Products and categories can also have their own SEO title (Phase 2 product and category forms).

**Why the shop showed only its name:** no logo was set (`"logo": ""`). Once a logo file is set, it appears.

## 11. Banners — `banner_frequency`, `banner_start`, and position

| Setting | Choices |
|---|---|
| `banner_frequency` | `ALWAYS` (every visit, default) · `SESSION` (once per visit) · `DAY` (once per person per day) |
| `banner_start` | `FIRST` (always banner 1) · `RANDOM` (a random banner each visit) · `NEXT` (the next banner each visit, in turn) |
| Position | Move `"banner"` inside `home_sections_json`. For example, `["categories", "banner", "bestsellers"]` puts it after the categories |

These combine freely: for example `DAY` + `NEXT` shows each person banner 2 tomorrow if they saw banner 1 today. The choice is applied before the page is drawn, so a banner never flashes and disappears. Up to **6** banners. Each banner can still have its own `starts_at` / `ends_at`.

## 12. Trust strip (the row of reasons to buy) — `trust_strip_json`, `show_trust_strip`

```json
"trust_strip_json": [
  { "icon": "truck",  "text": "Free delivery over ₹499" },
  { "icon": "cash",   "text": "Cash on Delivery" },
  { "icon": "refund", "text": "7-day easy returns", "link": "/pages/refund-policy/" },
  { "icon": "leaf",   "text": "100% natural" }
]
```

- Up to **6** items, **40** characters each. `link` is optional. `"show": false` hides one item without deleting it.
- Icons: open `/styleguide.html` → *Icons* to see every icon with its name (truck, cash, refund, shield, leaf, gift, award, heart, headset, badge-check, sparkle, flag, store and more). An unknown name shows a tick, and the build log says so.
- `"show_trust_strip": false` hides it everywhere. Leaving `"trust"` out of `home_sections_json` hides it on the home page only.
- With an empty list, the shop builds the strip from your settings (secure payments, COD, returns, delivery days).

## 13. Products — photos, options, description, key features, specifications

| What | Limit |
|---|---|
| Photos per product | **6**, or **6 per colour** (up to 12 colours, 60 photos in all). Choosing a colour shows that colour's photos |
| Option types per product | **3** at once (e.g. Colour + Size + Material) |
| Values per option | **20** (e.g. 20 colours, 10 sizes) |
| Combinations (SKUs) | **100** per product, each with its own price, MRP, stock and photos |
| Key features | **8** short points (120 characters each), shown next to the price |
| Specifications | **8** groups (e.g. General, Size & fit, Care) with **40** rows in total. Long lists fold behind "Show all" |
| Description | **20,000** characters, written in a Word-style editor (Phase 2) |

**Description editor (Phase 2):**
- Text: bold, italic, underline, strike, highlight, text colour (8 safe colours), text size (4), font (normal, heading, mono), capitals, subscript and superscript.
- Paragraphs: alignment (left, centre, right, justify), line spacing (1, 1.5, 2), paragraph spacing, indent.
- Building blocks: headings, bullet, numbered and tick lists, links, tables (header row, merged cells, striped / plain / bordered, column widths), note and warning boxes, quotes, dividers, pictures (left, right, centred, full width), two columns, undo/redo, and paste from Word with clean-up.

Everything is kept safe: the shop allows only these formats, so nothing harmful can be pasted in.

Swatch colours: common colour names get a round swatch automatically (Red, Maroon, Navy Blue, Bottle Green…). For your own names, give the exact colour in `swatches`. Unavailable combinations are shown crossed out, never hidden.

Card and gallery shape: `product_image_ratio` = `SQUARE` (default) · `PORTRAIT` (4 : 5, best for clothing) · `LANDSCAPE` (4 : 3). With `product_image_fit` = `cover`, photos fill the box with no blank space. See **docs/IMAGE_GUIDE.md** for picture sizes.

## 14. Delivery estimate — `delivery_display`, `delivery_custom_text`

| `delivery_display` | Product page shows |
|---|---|
| `DATE` (default) | Pincode box → "Delivery by Thu, 8 Oct" (uses each pincode's delivery days) |
| `DAYS` | Pincode box → "Delivery in 3 days" |
| `TEXT` | Your own sentence, e.g. "Ships within 24 hours from Coimbatore" (`delivery_custom_text`, up to 80 characters), with no pincode box |

## 15. Any colours and gradients — `primary_color`, `secondary_color`, `accent_color`, `header_bg`, `catbar_bg`, `announcement_bg`, `footer_bg`, `hero_bg`, `button_bg`, `page_bg`

The six themes are only quick starting points. **Any colour** can be used for the brand colours, and each area of the shop can have its own colour **or gradient**:

| Setting | Area |
|---|---|
| `header_bg` | Top bar (logo, search, cart) |
| `catbar_bg` | Category bar under it |
| `announcement_bg` | Thin bar at the very top |
| `footer_bg` | Footer |
| `hero_bg` | Welcome banner (when no banner photo is set) |
| `button_bg` | Main buttons (Add to cart, Buy now…) |
| `page_bg` | Page background (light colours only) |

Each can be written as:
- `"#7C3AED"` — one colour
- `"linear-gradient(135deg, #7C3AED, #DB2777)"` — a gradient of 2 or 3 colours, at any angle (0–360)
- `"radial-gradient(#7C3AED, #DB2777)"` — a round glow
- `""` — use the theme colour

**Automatic safety:**
- Text on each area is set to white or near-black, whichever is readable on every part of the gradient.
- The build warns when no text colour can be read well.
- Search suggestions and drop-down menus stay readable.
- In dark mode, light areas are darkened automatically.
- Only real colour codes are accepted, so nothing else can be slipped into the page.

Admin (Phase 2) gets colour pickers with a live preview and a contrast meter.

## 16. Footer — `footer_bg`, `footer_sections_json`, `footer_columns_json`, `footer_about_text`, `footer_show_contact`, `footer_show_social`, `footer_show_hours`, `footer_copyright_text`, `footer_text`

```json
"footer_sections_json": ["about", "care", "policies", "payments"],
"footer_columns_json": [
  { "title": "Shop", "links": [ { "text": "Sarees", "href": "/c/sarees/" }, { "text": "New arrivals", "href": "/search/?sort=newest" } ] },
  { "title": "Follow us", "links": [ { "text": "Instagram", "href": "https://instagram.com/yourshop" } ] }
],
"footer_about_text": "Family-run sweet shop since 1985.",
"footer_copyright_text": "© {year} {shop}. All rights reserved."
```

- Built-in columns: leave a name out to hide it, and change the order to reorder. Column titles can be renamed in Shop wording.
- Your own columns: up to **4** columns × **8** links. A link can be a shop page (`/…`), a website (`https://…`), a phone (`tel:…`) or an email (`mailto:…`). Anything else is dropped.
- `footer_show_contact`, `footer_show_social` and `footer_show_hours` switch those parts on or off. An empty `footer_copyright_text` hides the copyright line.
- Footer links change colour smoothly on hover, with no underline.

## 17. Cover picture for the big banner — `hero_cover_json`

```json
"hero_cover_json": {
  "mode": "PHOTO",
  "desktop": "client/assets/cover-desktop.jpg",
  "tablet": "client/assets/cover-tablet.jpg",
  "mobile": "client/assets/cover-mobile.jpg",
  "alt": "Fresh sweets on a brass plate",
  "overlay": "#1E1B4B", "overlay_opacity": 40, "overlay_style": "SIDE",
  "image_opacity": 100, "background": "",
  "text_align": "LEFT", "text_valign": "MIDDLE", "text_color": "AUTO",
  "eyebrow": "", "title": "Fresh sweets for every festival", "subtitle": "Made in Coimbatore since 1985",
  "show_eyebrow": true, "show_subtitle": true, "show_button": true,
  "button_text": "Shop sweets", "button_link": "/c/sweets-snacks/",
  "focal_x": 50, "focal_y": 50
}
```

| Setting | Meaning | Limit |
|---|---|---|
| `desktop` / `tablet` / `mobile` | One picture per screen size, switched automatically by screen width (phone under 768 px, tablet under 1280 px, computer from 1280 px) | **Exactly 3 : 1 / 2 : 1 / 1 : 1** (±2 %). At least 1440 × 480 / 1024 × 512 / 720 × 720. Under 600 / 450 / 350 KB. A wrong shape is not used |
| `mode` | `PHOTO`: your words over the photo. `ARTWORK`: a finished design with its own words, never cut | — |
| `overlay`, `overlay_opacity`, `overlay_style` | Shade over the photo so words stay readable: any colour or gradient, 0–80 %, covering the whole picture (`FULL`), fading from the words' side (`SIDE`) or from the bottom (`BOTTOM`) | 0–80 % |
| `image_opacity` | Picture strength. Lower lets the `background` colour show through | 20–100 % |
| `background` | Colour or gradient behind the picture. It also fills the sides of an ARTWORK picture on very wide screens | — |
| `text_align`, `text_valign`, `text_color` | Where the words sit and their colour (`AUTO` picks white or dark from the shade) | — |
| `eyebrow`, `title`, `subtitle`, `button_text`, `button_link` | The words. Empty = "Welcome to" / shop name / tagline / "Shop now" | 40 / 80 / 160 / 30 characters |
| `show_eyebrow`, `show_subtitle`, `show_button` | Switch each one on or off | — |
| `focal_x`, `focal_y` | The part of a photo that must stay visible when a screen trims it | 0–100 % |
| `link` | ARTWORK only: tapping the picture opens this page | — |

How it behaves:
- The cover replaces the colour welcome banner. Photo banners (`hero_banners_json`) still take priority when set.
- The right picture is requested early, so the banner appears fast.
- On very wide screens the banner stops at 720 px tall.

## 18. Preview before publishing

There are two kinds of preview. Both are free.

1. **Design preview — `/preview/`** (instant, nothing published):
   - Every look setting in this document can be changed with simple controls, or as settings text.
   - The shop is shown at once on a phone, tablet, laptop and big screen side by side, in light or dark mode, as a first-time or returning visitor, with or without pop-ups.
   - It covers the home, category, product, all-products, cart and contact pages, plus the browser-tab icon and tab name.
   - Pictures can be tried from your computer before uploading, with an instant ✓ / ⚠ size and shape check.
   - It uses exactly the same page templates and the same look code (`public/js/look.js`) as the real shop. The **Checks** tab runs the same checks as the build.
   - Stays in your browser. **Copy settings for GitHub** gives the finished "display" section.
2. **Private test copy** (a full second shop):
   - Any GitHub branch other than `main` (for example `preview`) is built by Cloudflare at `https://preview.<project>.pages.dev`.
   - It carries a yellow "Preview copy" strip, is hidden from search engines, and has ordering switched off.
   - Cloudflare's **Access policy** makes it private to you.
   - **Publish** = merge the branch into `main` on GitHub. See Setup Guide 8e.

From Phase 2, the admin's **Save draft** and **Publish** buttons do the GitHub part, and its look screens show the same live preview.

## Legal note (India) — why some things are not allowed

The Consumer Protection Authority's *Guidelines for Prevention and Regulation of Dark Patterns, 2023* (notified 30 November 2023) apply to online sellers. They forbid:
- **"False urgency"**, such as showing untrue popularity or quantities
- **"Nagging"**, meaning repeated disrupting requests

So this shop:
- calculates ratings and "bought" counts only from real data, never typed by hand
- rounds counts down, never up
- limits how often popups appear

Please don't add fake counts or timers for a client. It can get the client into legal trouble.
